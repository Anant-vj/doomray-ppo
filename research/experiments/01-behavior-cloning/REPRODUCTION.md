# Reproduction

## Inspect the published evidence

From this experiment directory, use the existing Python 3.13 environment with NumPy. The verifier reads the dataset and prints its verified counts. It leaves the game unopened.

```powershell
& $env:DOOM_PYTHON -B ./verification/check-dataset.py
Get-FileHash -Algorithm SHA256 ./evaluation/screening.jsonl
```

`evaluation/verified-counts.json` contains both the original source hash and the published ledger hash. The evaluation JSON uses paths relative to this experiment. `local-checkpoint-archive`, `approved-release`, and `operator-local-storage-policy` are logical locations for inputs an operator supplies. [The artifact manifest](artifact-manifest.json) records each file's source hash and, where normalization occurred, its published hash.

## Reconstruct the training source

Create a detached checkout on the external drive at the base release in `artifact-manifest.json`. Apply `source/implementation.patch` there. The patch also contains the code that generates the training spawn variants. Verify regenerated bytes against `training/variant-manifest.json` using the original starter fixtures and the bundled ViZDoom 1.3.3 training scenario. The included screening WADs are the exact as-run files.

```powershell
$artifact = (Resolve-Path .).Path
# Set this to an operator-owned checkout at the approved base commit.
$checkout = (Resolve-Path $env:DOOM_REPRO_CHECKOUT).Path
git -C $checkout apply --check (Join-Path $artifact 'source/implementation.patch')
git -C $checkout apply (Join-Path $artifact 'source/implementation.patch')
$env:PYTHONPATH = Join-Path $checkout 'env'
```

An exact training rerun requires the original raw u621 training parent from the local archive, with the digest in `training/ppo-only-precision-1-launch.json`. Its update metadata affects seed derivation. The read-only report verification above uses only public artifacts. Historical launchers preserve the recorded settings and cutoff checks. Use a separate local campaign directory with its own approved storage baseline and the Windows runner's external-drive paths.

Copy `demonstrations` into the fresh local campaign directory and assign that directory to `DOOM_WORK`. With the verified original parent path in `DOOM_PARENT_CHECKPOINT`, the original supervised command uses the held-out `defend-center` family. Run it from the detached checkout.

```powershell
& $env:DOOM_PYTHON -B -m training.behavioral_clone `
  --initialize $env:DOOM_PARENT_CHECKPOINT --validation-family defend-center --epochs 10
```

For each PPO continuation use `training.train` with CPU stack memory, four workers, horizon 64, 128 updates, 1,050 ticks, seed 2207, learning rate `8e-5`, the precision curriculum and the precision reward profile. The original switches are preserved in `source/run-precision-ppo.ps1`. Supply the local BC checkpoint for the imitation arm and the raw u621 checkpoint for the PPO-only arm. Keep the output campaign and run names distinct. [Launch configuration](training/bc-ppo-precision-launch.json)
